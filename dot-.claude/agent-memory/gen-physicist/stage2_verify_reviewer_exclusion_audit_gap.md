When PLAN-AUTHORING a Stage-2 cross-axis PASS-AND verify wave (N independent gates, each closing the held JOINT leg of a prior blind Stage-2 PASS-AND on a STAGE-1-CANDIDATE §VII theorem), the load-bearing reviewer-selection guard is `joint-theorem-promotion.md §"Stage-2 Axis-B Selection Protocol"`: two NON-AUTHOR axis-distinct reviewers, no workshop transcript, JOINT clauses PASS-AND'd.

**The audit tool `computations/_shared/_joint_theorem_independent_verify_audit.py --check-reviewers VII.XX --reviewers a,b` is NOT reliable for the newer §VII entry format (CG/CH/CI/CJ, S111-era, and likely all post-BZ entries).** Its `extract_stage0_authors` parser has a structural mismatch with that format, and NEITHER a one-line `AUTHORSHIP_LINE_REGEX` extension NOR a `REVIEWER_ASSIGNMENT_LINE_REGEX` broadening fixes it cleanly (I tried both in S112 W2 planning and reverted — git diff clean):

1. **Root cause A (under-detection)**: the CG-CJ author line reads `**Math-owners / Stage-0 authors (Stage-1 registrants, EXCLUDED from Stage-2 review ...):** <names>`. The bare word "authors" is NOT in the regex vocabulary (`PRIMARY|CO-AUTHOR|authorship|authoring|Sponsors`), so a genuine author silently passes the exclusion check → spurious EXCLUSION-PASS even when a reviewer IS an author.
2. **Root cause B (over-catch on the naive fix)**: adding `Stage-0 author|Math-owner` to `AUTHORSHIP_LINE_REGEX` DOES match the author line, but the block-wide `for full in KNOWN_AGENTS: if full in low` harvest then ALSO pulls in the candidate-reviewer names because the entries CO-LOCATE the author attribution AND the "Stage-2 reviewers (candidate) = einstein OR kaku ..." suggestion in the SAME prose block — polluting the author set so even legitimate reviewers FAIL.
3. **Root cause C (filter broadening discards real authors)**: broadening `REVIEWER_ASSIGNMENT_LINE_REGEX` to `(cross-review|stage-2 reviewer)` kills the author line itself, because that line literally contains "EXCLUDED from **Stage-2 review** per..." → authors discarded.

This is a genuine audit-redesign (per-line author/reviewer disambiguation on co-located prose), NOT a fix-now plan concern. Per scope discipline, BACK OUT the audit edit and **encode the exclusion guard explicitly in the plan**: (i) every gate block carries a literal `excluded_authors:` field with the Stage-0 author names (cross-checked against the registry entry's "Math-owners / Stage-0 authors" line); (ii) a §"Reviewer-selection guard" section enumerating the Axis-B Selection Protocol conditions 1-6; (iii) a §"Reviewer-non-collision cross-check" table proving ∅ intersection per theorem by direct set membership. The `--self-test` of the audit still PASSes (synthetic cases use the OLD format); the gap is format-specific to live CG-CJ entries.

**Why:** The audit's `--check-reviewers` returning EXCLUSION-PASS is necessary-not-sufficient for these entries; trusting it would ship a vacuous guard (PRU-Class-8-analog: a guard that doesn't fire). Manual set-intersection in the plan is the reliable check.

**How to apply:** Any future Stage-2 verify cohort over a §VII entry whose author line uses the "Math-owners / Stage-0 authors" idiom — do the exclusion check by READING the registry entry's author line + the entry's own embedded "Stage-2 reviewers (candidate)" suggestion (which the Stage-0 authors pre-vetted for axis-distinctness), pick from those candidates filtered for the exclusion, and PROVE ∅ intersection in the plan's cross-check table. Cross-gate reviewer REUSE across DIFFERENT theorems is admissible (the exclusion is per-theorem, not per-session) — e.g. connes can review CH and CJ if it authored neither.
