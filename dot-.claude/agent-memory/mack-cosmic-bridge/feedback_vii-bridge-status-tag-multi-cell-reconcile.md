A §VII cross-pillar-bridge registry entry carries a Level-2 (or any) status tag REDUNDANTLY across multiple cells of the SAME entry:
- the **three-level ladder** table's Level-N status column (rightmost cell), AND
- the matching **IS-not-IN anatomy** element (Element 4 = "Algebraic envelope" carries the Level-2 sub-class), AND
- sometimes the **parent-host slot** (a separate STAGE-1-CANDIDATE `### §VII.AV` host above the STAGE-3 sub-slot can carry its own copy in its header).

**Why:** S116-W8 §A8 routed me a discharge of `REGISTRY-INCOMPLETE-PENDING-PROXY-REFINEMENT → PROXY-REFINEMENT DISCHARGED / Level-2 BINDING` on §VII.AV.STATE-PROJ, but the spec enumerated only Element 3 (`registry:18817`) + Element 4 (`registry:18818`). The same tag ALSO lived in the ladder Level-2 status cell (`registry:18810`). Landing only the two enumerated loci would have left the ladder cell stale ⟹ the entry self-contradicts (Level-2 "pending" in one cell, "BINDING/DISCHARGED" in another) — the exact within-entry inconsistency no-technical-debt forbids. The workshop "What Changed" said "whole Level-2 envelope → BINDING DISCHARGED", confirming reconcile-all is faithful to intent, not scope-creep.

**How to apply:** before landing any discharge/supersede/down-tag on a §VII bridge entry, grep the ENTIRE entry block (header → next `### §VII` header) for the OLD tag string. Reconcile EVERY occurrence the discharge implies — but surgically (status cell text only; leave Level-1/Level-3/anatomy-description columns untouched). Do NOT touch a SEPARATE parent-host slot that is at a different STAGE (e.g. the STAGE-1-CANDIDATE `### §VII.AV` parent vs the STAGE-3-PERMANENT `.STATE-PROJ` sub-slot) unless the spec routes it — that's a different slot with its own lifecycle. Flag any reconcile-beyond-the-literal-spec in the §A-LANDED record + orchestrator summary so it's transparent, not silent.
