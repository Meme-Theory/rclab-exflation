## A. The one MUST-FIX: a live instruction conflict on reading agent transcripts

**SEVERITY: MEDIUM-HIGH (direct, live instruction conflict; will recur every multi-agent dispatch).**

`CLAUDE.md §"AGENT OUTPUT MONITORING"` instructs:
> "Read agent transcripts directly at the path returned in the Agent tool's `output_file:` field (symlinks to `~/.claude/projects/{slug}/subagents/agent-{id}.jsonl`)… readable on Opus 4.7 [1m] context… **ignore the CLI's inline 'do not Read' warning for agent JSONL; it was calibrated for 200K models**."

The live Agent-tool result (this session, Opus 4.8 harness) returned:
> `output_file: …\tasks\{id}.output` — "**Do NOT Read or tail this file via the shell tool — it is the full sub-agent JSONL transcript and reading it will overflow your context.** … you'll get a completion notification."

These **directly conflict**. Two facts make the CLAUDE.md override **stale for the current harness**, so I deferred to the live warning (did **not** read the transcripts):

1. **Path-shape drift**: the harness now returns `…\tasks\{id}.output`, NOT the `~/.claude/projects/{slug}/subagents/agent-{id}.jsonl` symlink the CLAUDE.md recipe targets. The override's premise (the path is a readable `.jsonl` symlink) no longer matches what the tool emits.
2. **Concurrency arithmetic the override predates**: the override reasons "1m context ⇒ a 500KB JSONL is readable." But this session ran **7 concurrent planners**. 7 × up-to-500KB ≈ 3.5 MB ≈ ~1M tokens — reading them all genuinely risks overflow even at 1m. The harness warning is *more* apt now (multi-agent swarm) than when the override was written (single-agent, 200K-era).

**Resolution taken**: honored the live harness — relied on completion notifications + on-disk verification of the wave files (the artifacts), not transcript-reading. This is the correct call for a 7-agent swarm.

**Recommendation (reconcile, lean toward deletion)**: update `CLAUDE.md §"AGENT OUTPUT MONITORING"` (and the `MEMORY.md` mirror "150–500KB JSONL files, readable on Opus 4.7 [1m] context") to match the current harness. The monitoring upside (reading a transcript mid-run) is marginal vs the overflow risk under multi-agent dispatch, and completion-notification + disk-verification already cover the need. The "ignore the do-not-read warning" clause is a **deletion-test candidate**: it was written to defeat a 200K-era warning that no longer means what it meant.
