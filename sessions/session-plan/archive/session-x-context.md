## §4. Gate architecture — expansion-primary (`SURVEY → EXPAND → VERIFY`)

Each wave (W1–W8) has THREE gates. The center of mass is G2 (expansion). All three emit the
canonical dual-SHA verdict line + WP section via a small closure script, so the audit ladder +
`_yaml_gate_validator.py` stay intact for prose gates.

- **`WX-W{i}-1` AGGREGATE-DOMAIN-SURVEY (trigger AUDIT)** — the comprehensiveness ENGINE. The
  executor maps the document's DOMAIN against the whole knowledge base: query every pertinent
  entity class (`search_knowledge`, `trace_entity`, `list_entities`, `get_constant`,
  `query_entity` over theorems / closed / gates / sessions / open / constants) for the subject
  area, across all ~93 sessions. Output: (a) a **current whole-project state-of-domain map** and
  (b) a **GAP ANALYSIS** — everything the project knows in this domain that the document does NOT

  one-line "where it belongs in the document." PASS = the survey covers the domain's pertinent

  claims re-checked). This gate is FAILED if it only audits existing claims.

- **`WX-W{i}-3` RECONCILE+VERIFY (trigger VERIFY)** — QA over the expanded document: every claim

## §5. Aggregate-domain-survey directive (G1, MANDATORY — this is the heavy pass)

The executor's first gate is a WHOLE-DOMAIN survey, not a claim-by-claim audit. For the document's
subject area, sweep the knowledge base broadly:

```
search_knowledge("<domain topic 1>") ; search_knowledge("<domain topic 2>") ; ...   # broad, many queries
trace_entity("<each major mechanism / observable / theorem in the domain>")          # full evidence chains
list_entities("theorems") / list_entities("closed") / list_entities("gates")         # what exists now in-domain
get_constant("<each constant the domain touches>")                                   # current values + Superseded flags
query_entity(table, id)                                                              # drill into specifics
```

The survey is COMPLETE when the document's domain has been swept across the pertinent entity classes
and the GAP between "what the project knows" and "what the document covers" is enumerated with
citations. Expect many KB queries (tens), not a handful. Record the query manifest in the gate's WP
**MCP Pre-Compute Audit** block (mandatory per `workingpaper.md` Rule 3). A gap row without a KB
citation is "imagined" per the derivative-output discipline.
