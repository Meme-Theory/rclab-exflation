## §EVOI — Methodology and the honesty caveat

```
EVOI = P(pass) × |ΔP(pass)| + P(fail) × |ΔP(fail)|
```
- `ΔP(pass)` / `ΔP(fail)` = how far the framework's standing moves up/down on that verdict (the *leverage*).
- The highest-EVOI computation gets Wave-1 priority.
- **Effort-based**: the standing rises when work is done — eliminating a wrong corridor IS information. A FAIL that closes a route has real EVOI.

**HONESTY CAVEAT (load-bearing).** The numeric EVOI values below are **ordinal leverage proxies**, not calibrated probabilities. They are derived from `atlas-08 §0` tier assignments × current verdict status × leverage class — the same qualitative judgment the S83 table used (it openly admitted "[rough calc — actual priority is qualitative]"). They order the queue; they are **not** to be quoted as probabilities. A proper `P(pass)` elicitation gate is pre-registered as a maintenance item (§7). Do not let a 3-significant-figure EVOI masquerade as a measurement — that false precision is part of what let the dead table look authoritative.
