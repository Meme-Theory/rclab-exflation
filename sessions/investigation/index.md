# Investigations Index

Cross-reference of every `investigation-[n]` to its **free-form topic**, its driver (what
spawned it), lifecycle status, plan, outputs, and what it went on to drive.

Investigations are the project's **exploratory track** — structurally the same pipeline as
sessions (`/rclab-plan` → `/rclab-coordinate` → `/rclab-investigate`), but seeded from a
free-form input (an agent survey, a synthesis, any springboard document) rather than from a
prior session's carry-forwards. A `investigation-1`-style wholesale survey drives new
`investigation-[n]` efforts; each effort can in turn seed the next. Results that must become
permanent are **promoted into a session** (lifted as a carry-forward into a `/rclab-plan`
session-mode plan), not held here — see `.claude/rules/gate-verdicts.md §"Investigation-Track
Canonical Path"` (track-local boundary).

## Lifecycle states

- `SURVEYING` — agents dispatched, outputs landing (a manual or planned open-ended survey). No PASS/FAIL gates.
- `PLANNED` — `investigation-{n}-plan` exists (`/rclab-plan --investigation` ran); not yet executed.
- `EXECUTING` — `/rclab-coordinate` is dispatching the investigation's waves (compute / solo / review / workshop gates).
- `ANALYZING` — `/rclab-investigate` is mining the outputs into a synthesis + next-investigation seed.
- `CLOSED` — synthesis written; Outputs + Drives recorded.

## How a new investigation is born (the recursion)

```
investigation-1 survey outputs (free-form)
   │
   ▼  /rclab-investigate --investigation 1   ← writes _synthesis.md + a next-investigation seed; housekeeps THIS index
   │
   ▼  /rclab-plan --investigation 2 --from investigation-1/_synthesis.md (or a chosen seed)
   │      ← translates seed gaps/bridges/next-steps into a mixed-type wave plan; REGISTERS investigation-2 here
   ▼
   /rclab-coordinate sessions/investigation/investigation-2/investigation-2-plan-index.md
   │      ← juggles compute / solo / review / workshop gates
   ▼
   /rclab-investigate --investigation 2       ← analyzes; may seed investigation-3; housekeeps this index
```

A single survey can fan out into several focused investigations (one per high-leverage cluster);
each row above records which seed drove it (Driver / Seed column) and what it drove (Drives column),
so the genealogy is queryable from this one file.
