S115 W2-1 `CF-S115-VIICK-D4-DISCHARGE-UNCONDITIONAL` (§VII.CK D4 right-regular SU(3)_R = external-as-a-coupling).

**1. Same-session shared-slot dependency = a mechanical-closure PRE-REG-INC branch, NOT a static input pin.** The two gates verify DISTINCT clauses of the same slot (W1-1: D1–D3 closed-class; W2-1: D4-external). Register them as DISTINCT gate IDs; do NOT conflate. The dependency is read at W2 dispatch from the W1 verdict file (`grep S115-VIICK-STAGE2-VERIFY computations/session-N/sN_gate_verdicts.txt`):
- W1-1 = PASS ⇒ run the full verify; on PASS-AND the closeout does the single-shot bridge-landing tag-flip STAGE-3-PERMANENT → -UNCONDITIONAL.
- W1-1 ≠ PASS ⇒ **mechanical-closure PRE-REG-INC** per `mechanical-closure-discipline.md §"When mechanical closure IS acceptable"` item 1 (plan-ANTICIPATED prereq-block; NOT post-hoc plan editing). `value='PRE-REG-INC_blocked_by_S115-VIICK-STAGE2-VERIFY_<status>'` (FAIL/PRE-REG-INC, NEVER PASS); closure script updates WP §section IN SAME RUN; defer to S+1.
- Because the wave has 1 gate, covered-count 1 < `N_PLANNING_DEFECT_THRESHOLD=4` ⇒ a prereq-block closure here is NOT a planning-defect signal, it's correct sequenced-dependency behavior. Pin in `machinery_pin_map`: read the W1 gate-ID from the verdict file as a `<computed-at-runtime>` input.
- The shared-slot registry file SHA is `<computed-at-runtime>` (NOT a static plan-freeze pin): W1-1's tag-flip EDITS the registry mid-session, so the W2 runtime SHA necessarily differs from the plan-freeze full-file SHA. The dependency is on W1-1's flip (verdict-file-read), not on a frozen registry byte-state. Record the plan-freeze full-file SHA as a REFERENCE-ONLY pin and say so.

**2. Reviewer-exclusion via COMPANION-THEOREM inheritance (downstream-inheritance reach, condition 2b).** §VII.CK is the STRUCTURAL-ORTHOGONAL-COMPANION of §VII.BL, sharing the multiplicity-scalar/commutant mechanism. The D4-discharge IS that commutant argument. So an agent that co-authored §VII.BL (here `kaluza-klein-theorist` — §VII.BL Stage-0 co-author + registry-landing author/reviewer-of-record, registry L21197/L21276) has downstream-inheritance reach into §VII.CK's D4 verify and is EXCLUDED — even though it is NOT named anywhere in the §VII.CK block itself. The `--check-reviewers VII.CK` author-parser will NEVER catch this (it only reads the §VII.CK block; KK is not in it). Encode it manually in `excluded_authors` with the companion-inheritance basis cited. Axis-B picks an explicitly §VII.BL-NON-inheriting agent (here `volovik`, pinned by the context file precisely for that reason). Generalize: when verifying a clause on a slot that is a structural-companion of another theorem and reuses that theorem's mechanism, the companion's authors inherit reach — exclude them.

**3. Disjoint-reviewer-pair PIN across the TWO promotions on the same slot (cross-promotion-independence axis, §EVOI.BF).** When two Stage-2 promotions land on the SAME slot (W1-1 closed-class, W2-1 UNCONDITIONAL), the §EVOI.BF cross-reviewer-independence basis wants the two reviewer PAIRS DISJOINT (4 distinct reviewers). So if both gates' Axis-A pools share a candidate (W1-1 pinned `{lizzi, kitaev}`, W2-1 left "lizzi OR spectral-geometer"), a coordinator could pick the shared one at dispatch ⇒ independence collapse. Fix: PIN the second gate's Axis-A to the NON-shared option (`spectral-geometer`), drop the OR-optionality, and document `lizzi` as RESERVED for W1-1. This is an ADDITIONAL exclusion on a DIFFERENT axis than `excluded_authors` (which is Stage-0-authorship): lizzi passes the Stage-0 exclusion cleanly but is still inadmissible for W2-1 by the disjoint-pair requirement. Leaving an OR-pool where the sibling gate's pin overlaps it is a latent independence-collapse the validators do NOT catch (both still PASS) — pin it at plan-freeze. (S115: team-lead refinement after W1 pinned `{lizzi, kitaev}`; end-state W1-1 `{lizzi,kitaev}` ⊥ W2-1 `{spectral-geometer,volovik}`.)

**Why:** (1) a shared-slot dependency that is NOT pre-registered as a mechanical-closure branch forces a post-hoc decision at dispatch (Class-3 risk) or a forced run on an unflipped slot; (2) the audit tool's per-slot author scan structurally cannot see companion-theorem inheritance, so trusting it ships a vacuous guard (a reviewer who DID inherit the reading passes); (3) an Axis-A OR-pool overlapping the sibling promotion's pinned pair is a latent cross-promotion-independence collapse that PASSes the validators. All three are PRU-Class-8-analog guard-doesn't-fire failures.

**How to apply:** Any Stage-2 verify whose slot (a) is concurrently modified by a sibling same-session gate → pre-register the verdict-file-read dependency + the mechanical-closure PRE-REG-INC branch with `value='PRE-REG-INC_blocked_by_<sibling-gate>_<status>'`; and/or (b) reuses a DIFFERENT theorem's mechanism (companion/orthogonal-companion) → add that theorem's Stage-0 authors/reviewer-of-record to `excluded_authors` with the inheritance basis, and prove ∅-intersection in the cross-check table by direct set membership (never via `--check-reviewers`). The audit's items 1–6 still get pinned (dispatch_parallelism / axis_distinctness / workshop_context_isolation / PASS-AND-logical-AND / reviewer_machinery_not_self_authored) — item 6 is audit-clean when the selection-rule + commutant machinery originate in the workshop + a permanent anchor (`proven_384`), so both reviewers APPLY machinery they did not author.
