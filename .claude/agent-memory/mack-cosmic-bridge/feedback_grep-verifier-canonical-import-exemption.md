When I land a falsifier sub-row via a thin **grep-verifier** (the artifact-existence pattern: the script greps `falsifier-master-inventory.md` for the new sub-row + anchor and emits a verdict by set-membership, no numerical compute), the verifier consumes NO canonical constant. The `python-validate.sh`/`python-validate.py` PostToolUse hook then fires a **Check-1 WARN** ("Missing `from canonical_constants import ...`"). This WARN is **expected and correct** — keep the verifier constant-free.

**Why:** The hook is WARN-only **by deliberate project design** ("blocking would wedge any edit touching a legacy script"; python-validate.sh §POLICY) with policy "Fix when convenient or tag as local." It is purely regex-based (Check 1 only clears if a literal `from canonical_constants import` line exists — there is NO in-file suppression marker). Plans for these gates pre-register the exemption explicitly (S117 W0-2: `output_artifacts.script.must_contain` = `print_verdict_payload` only, with the note "the canonical_constants-import marker is intentionally relaxed for this artifact-existence verifier"; `input_files` note "reads NO canonical_constants.py"). Adding the import to silence the WARN would EITHER inject a dead unused import (no-technical-debt violation) OR — if made genuinely used — change the pre-registered `audit_sha256` input set away from {script, inventory, anchor} to include canonical_constants.py, a real PRU deviation from the frozen machinery pin. The master "correct ALL warnings" rule targets real defects, not a WARN-only false-positive the project's own policy + the plan both sanction.

**How to apply:** For any `s{N}_*_verify.py` / `s{N}_*_landing_verify.py` falsifier-surface grep-verifier I author (sole-writer role, `feedback_mack-bridge-role.md`): keep it import-free of `canonical_constants`; document the exemption in the script docstring citing the plan's must_contain/input_files notes; compute `content_sha256 = sha256(landed sub-row block text)` and `audit_sha256 = sha256(script ‖ inventory ‖ pinmap{script-SHA, inventory-SHA, anchor})`; accept the WARN. In the WP §"Output Artifacts" item (1), state the exemption is pre-registered (not an uncorrected defect). Do NOT re-adjudicate per landing. See [[feedback-mack-bridge-role]] for the sole-writer scope; the dual-SHA pattern follows `.claude/templates/script-template.py` print_verdict_payload but drops the canonical_path from compute_dual_sha.
