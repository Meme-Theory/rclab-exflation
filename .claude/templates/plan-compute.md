# Compute Plan Template

Plan files come in two shapes, governed by `/rclab-plan --consolidate` vs `--fanout`:

| Shape | One file per | When |
|:------|:-------------|:-----|
| Consolidated | session — `session-{N}-plan.md` | small sessions (≤4 waves, ≤4K aggregate WP lines) |
| Fanout (default) | wave — `session-{N}-plan-w{i}.md` + thin `session-{N}-plan-index.md` | everything else; per-wave files prevent the S87 W1b unified-WP runtime-append failure mode |

Both shapes share the per-gate block. Authoritative gate-block schema:

- `.claude/templates/r3-yaml-gate-block.yaml` — 8-item PRDR YAML scaffold (S84+ preferred; consumed by `computations/_shared/_yaml_gate_validator.py`)
- `.claude/templates/pru-pre-registration-template.md` — legacy prose gate block + R3 YAML reference

## Consolidated session plan

```markdown
# Session {N} Plan: {Topic Title}

**Date**: {date}
**Author**: Team-lead (generated by /rclab-plan, planner: {planner-type})
**Format**: Parallel single-agent computations across {W} waves
**Source**: {which sessions/syntheses informed this plan}
**Motivation**: {1-2 sentences: why this session, why now}
**Results file**: `sessions/session-{N}/session-{N}-results-workingpaper.md`

## §I. Session Objective

{1-2 paragraphs: what this session resolves, what the pre-registered master gate is, if any.}

## §0.10 PRU Pre-Registration

{Aggregate of all gate `machinery_pin_map` entries across the session, per
`.claude/rules/epistemic-discipline.md §"Pre-Registration Completeness"`.
Required for sig_4 of the v3 closure ladder.}

## §II. Wave Structure

{ASCII dependency graph: which waves can run in parallel, which depend on prior verdicts.}

## §III. Wave {M}: {Wave Title}

{One §III subsection per wave. Within a wave, all gates are independent.}

### W{M}-{L}: {Gate ID}

{R3 YAML gate block per `.claude/templates/r3-yaml-gate-block.yaml`. Fill every required field: identity (gate_id, schema_version="R3", trigger, classification, agent_type, hypothesis), method, the 8 PRDR checklist items, verdict rubric (PASS/FAIL/INFO meanings), effort, substrate framing.}

## §IV. Constraint Gates Summary

| ID | Type | Condition | Fires If | Consequence |

## §V. Decision Points

**After Wave {M}**: if {condition A} → {action A}; if {condition B} → {action B}.

## §VI. Execution Notes

Python: `"phonon-exflation-sim/.venv312/Scripts/python.exe"` (see `.claude/rules/math-scripts.md §"Environment"` for GPU vs CPU dispatch rules)
Output: `computations/session-{N}/` (per-session gate scripts s{N}_*.py, verdict file, npz, png); `computations/_shared/` is shared INFRASTRUCTURE only (canonical_constants, helpers, audit scripts) — per the CLAUDE.md project structure
Script prefix: `s{N}_`
Verdict file: `computations/session-{N}/s{N}_gate_verdicts.txt` per `.claude/rules/gate-verdicts.md`
Each gate writes results ONLY to its designated section in the working paper.
No TeamCreate — all agents are independent Agent tool calls.
```

## Per-wave plan file (fanout)

```markdown
# Session {N} Plan — Wave {i}: {Theme}

**Date**: {date}
**Author**: {planner-type} (generated by /rclab-plan per-wave swarm)
**Owner agent**: {subagent_type — reviewer-origin for this wave's theme}
**Plan source**: `sessions/session-plan/session-{N}-context.md` §"Wave {i} items"
**Working paper**: `sessions/session-{N}/session-{N}-w{i}-workingpaper.md`

## Wave {i} Summary

{One paragraph: what this wave resolves; what the carry-forward source was.}

## Wave {i} Decision Point Prerequisites

{Which upstream verdicts (S{N-1} or earlier this session) gate any item in this wave. Reference by gate ID + verdict file path. If a prereq is unmet at dispatch time, the gate honestly closes per `.claude/rules/mechanical-closure-discipline.md`.}

## §W{i}-1. {Gate ID 1}

{R3 YAML gate block per `.claude/templates/r3-yaml-gate-block.yaml`. Mandatory fields per the 8-item PRDR checklist.}

## §W{i}-2. {Gate ID 2}

{...one block per gate in this wave...}

## Wave {i} → Wave {i+1} Decision Point

{If Wave {i+1} consumes Wave {i} outputs: which gates, what verdict patterns trigger which downstream action. Document branching for each PASS/FAIL/INFO outcome.}

## Wave {i} Machinery-Enumeration Pin

{Aggregate of all gate `machinery_pin_map` entries in this wave, per
`.claude/rules/epistemic-discipline.md §"Pre-Registration Completeness"` PRDR.
This is what `_yaml_gate_validator.py` reads for sig_4 of the v3 closure ladder.}

## Wave {i} Input-SHA Ledger

{Every input file this wave's gates consume, with expected SHA-256 per `.claude/rules/gate-verdicts.md`. Static files get precomputed hashes; dynamic inputs marked `<computed-at-runtime>`. Cross-checked at plan-freeze by `computations/_shared/_plan_upstream_pin_validator.py`.}
```


## Plan-Authoring Disciplines (cross-references)

The plan author MUST satisfy these rules at plan-freeze:

| Concern | Authoritative source |
|:--------|:---------------------|
| Per-gate PRU/PRDR completeness | `.claude/rules/epistemic-discipline.md §"Pre-Registration Completeness"` |
| Verdict-line schema + canonical path | `.claude/rules/gate-verdicts.md` |
| Verdict-source pointer (never `expected_verdicts: [...]`) | `.claude/rules/gate-verdicts.md` + S86 W0a-5: use `verdict_source: computations/session-{N}/s{N}_gate_verdicts.txt` |
| Source-Reconciliation pin-vs-canonical drift | `.claude/rules/epistemic-discipline.md §"Source Reconciliation"` |
| Substrate-first pin provenance + SCHEMATIC level pin | `.claude/rules/substrate-first-canonical-sourcing.md` |
| Substitution chain for sign/direction/threshold claims | `.claude/rules/math-scripts.md §"Double-Check Logic Before Compute"` |
| METHODOLOGY-class gates (M1-M4 conjunction + allowlist) | `.claude/rules/wave-classification.md` + `.claude/rules/methodology-wave-allowlist.md` |
| Cross-pillar bridge entries (5-anatomy + 3-level) | `.claude/rules/cross-pillar-bridge-anatomy.md` |
| `a_n^{regulator}` tagging on Seeley-DeWitt citations | `.claude/rules/regulator-pin-discipline.md` |
| Action-item 7-field format in carry-forwards / decision points | `.claude/rules/output-standards.md` |
| Carry-forward 4-field spec inheritance from prior WP | `feedback_fix-in-session-never-defer.md` + `Investigating-Workshops.md §"Cross-references"` |
| No hygiene padding in carry-forward queue | `feedback_fix-in-session-never-defer.md` |

A gate block missing any required PRU/PRDR field, or pinning a non-canonical verdict-file path, is PRU-vulnerable (Class 8 plan-property failure) and will not pass the validator suite at plan-freeze.
