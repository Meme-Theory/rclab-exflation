# Investigation Plan Template

The investigation pipeline (`sessions/investigation/`) is the **structural mirror** of the
session pipeline. This template is the investigation analog of `.claude/templates/plan-compute.md`;
it shares that template's per-wave / consolidated / plan-index shapes and the same per-gate
block schema. **Only three things differ** from a session plan:

1. **Seed provenance** — an investigation plan is generated by `/rclab-plan --investigation`
   from a **free-form input** (an investigation agent's survey output, a synthesis, any
   exploratory document), NOT from a prior session's WP carry-forwards.
2. **Namespace** — files live under `sessions/investigation/investigation-{n}/` and
   `computations/investigation-{n}/` (see the path table below), not `session-{N}`.
3. **Mixed gate types** — a single investigation wave may carry `compute`, `review`,
   and `workshop` gates side by side. Each gate declares its `gate_type` per
   `.claude/templates/r3-yaml-gate-block.yaml`. `/rclab-coordinate` juggles the three dispatch
   patterns directly. (There is NO `solo` gate_type: a physics gate is always `compute`,
   dispatched to its specialist research agent — never run inline by the orchestrator, which
   is not weight-positioned to compute. The no-spawn mode is `/rclab-solo`, a SEPARATE session
   launched as a research agent via `claude --agent <agent>`, not a per-gate type.)

Everything else — the R3 gate-block schema, the PRDR discipline for compute gates, the
substrate-first framing, the carry-forward math-vs-non-math split — is identical to the session
pipeline. Read `plan-compute.md` for the shared shape; this file documents only the deltas.

| Shape | One file per | When |
|:------|:-------------|:-----|
| Fanout (default) | wave — `investigation-{n}-plan-w{i}.md` + thin `investigation-{n}-plan-index.md` | everything else (per-wave files prevent the unified-WP runtime-append failure mode, S87 W1b) |
| Consolidated | investigation — `investigation-{n}-plan.md` | small efforts (≤4 waves, ≤4K aggregate WP lines) |

## Namespace (path table)

```
sessions/investigation/index.md                                       # the registry (rclab-plan registers; rclab-investigate housekeeps)
sessions/investigation/investigation-{n}/
  investigation-{n}-seed.md            # the free-form input digest (Phase-1 of rclab-plan; cites the source doc(s))
  investigation-{n}-partition.md       # wave partition manifest (theme + owner + gate_type per item)
  investigation-{n}-plan-index.md      # fanout index (consolidated: investigation-{n}-plan.md)
  investigation-{n}-plan-w{i}.md       # per-wave plan (MIXED gate types)
  investigation-{n}-w{i}-workingpaper.md   # per-wave WP
  investigation-{n}-results-index.md   # thin index of per-wave WPs
  investigation-{n}-{short}-synthesis.md   # review-gate deliverables (rclab-review pattern)
  workshops/{slug}.md                  # workshop-gate deliverables (rclab-workshop pattern)
computations/investigation-{n}/
  inv{n}_w{i}_{slug}.py                # compute-gate producing scripts
  inv{n}_gate_verdicts.txt             # compute verdict ledger (gate-verdicts.md §"Investigation-Track Canonical Path")
  inv{n}_w{i}_{slug}.npz / .png        # compute data + plots
```

The verdict file is emitted via `emit_verdict(session={n}, track="investigation", ...)`. Only
`compute` gates emit verdict lines; `review`/`workshop` gates close by artifact-existence.

## Per-wave plan file (fanout)

```markdown

**Date**: {date}
**Author**: {planner-type} (generated by /rclab-plan --investigation per-wave swarm)
**Owner agent**: {subagent_type — domain owner for this wave's theme}
**Seed**: `{free-form source doc(s) this wave's items were translated from}`  ← investigation analog of "Plan source"
**Plan source**: `sessions/investigation/investigation-{n}/investigation-{n}-seed.md` §"Wave {i} items"
**Working paper**: `sessions/investigation/investigation-{n}/investigation-{n}-w{i}-workingpaper.md`

## Wave {i} Summary

{One paragraph: what this wave resolves; which seed items (gaps / contradictions / assumptions /
refinements / bridges / highest-leverage-next-steps) it translates; the gate-type mix.}

## Wave {i} Gate-Type Manifest

{One row per gate: gate_id | gate_type (compute|review|workshop) | one-line scope. This is the
manifest /rclab-coordinate reads to branch dispatch. A wave may be single-type or mixed.}

| Gate ID | gate_type | Scope |
|:--------|:----------|:------|
| INV{n}-W{i}-1 | compute | ... |
| INV{n}-W{i}-2 | workshop | ... |
| INV{n}-W{i}-3 | review | ... |

## Wave {i} Decision Point Prerequisites

{Which upstream verdicts / deliverables gate any item in this wave. compute prereqs reference
inv{n}_gate_verdicts.txt by gate ID; review/workshop prereqs reference the upstream deliverable md.
If a prereq is unmet at dispatch, the gate honestly closes per mechanical-closure-discipline.md.}

## §W{i}-1. {Gate ID 1}

{R3 YAML gate block per `.claude/templates/r3-yaml-gate-block.yaml`. Set `gate_type` explicitly.
- compute: fill all 8 PRDR items + verdict rubric + output_artifacts (with verdict_line).
- review: fill the `review:` block (agents / sources / output_paths / context); PRDR numerics N/A;
  output_artifacts = one synthesis md per agent (no verdict_line).
- workshop: fill the `workshop:` block (2 agents / rounds / sources / output_path / adjudication_question /
  context); PRDR numerics N/A; output_artifacts = the workshop md (no verdict_line).}

## §W{i}-2. {Gate ID 2}

{...one block per gate in this wave; types may be mixed...}

## Wave {i} → Wave {i+1} Decision Point

{If Wave {i+1} consumes Wave {i} outputs: which gates, what verdict/deliverable patterns trigger
which downstream action. Document branching for each PASS/FAIL/INFO (compute) or
landed/not-landed (review/workshop) outcome.}

## Wave {i} Machinery-Enumeration Pin

{Aggregate of all COMPUTE gate `machinery_pin_map` entries in this wave, per
`.claude/rules/epistemic-discipline.md §"Pre-Registration Completeness"` PRDR. review/workshop gates
contribute nothing here (no producing script). This is what `_yaml_gate_validator.py` reads for the
compute subset.}

## Wave {i} Input-SHA Ledger

{Every input file this wave's COMPUTE gates consume, with expected SHA-256 per
`.claude/rules/gate-verdicts.md`. review/workshop gates list their `sources` here for traceability
but the SHA pin is advisory (the deliverable is a synthesis, not a SHA-pinned numerical output).}
```

## Plan-Authoring Disciplines (cross-references)

The plan author MUST satisfy these at plan-freeze. The first block is shared with the session
pipeline; the second block is investigation-specific.

### Shared with `plan-compute.md` (apply to compute gates)

| Concern | Authoritative source |
|:--------|:---------------------|
| Per-gate PRU/PRDR completeness (compute) | `.claude/rules/epistemic-discipline.md §"Pre-Registration Completeness"` |
| Verdict-line schema + canonical path | `.claude/rules/gate-verdicts.md` (use the **Investigation-Track** path) |
| Source-Reconciliation pin-vs-canonical drift | `.claude/rules/epistemic-discipline.md §"Source Reconciliation"` |
| Substrate-first pin provenance + SCHEMATIC level pin | `.claude/rules/substrate-first-canonical-sourcing.md` |
| Substitution chain for sign/direction/threshold claims | `.claude/rules/math-scripts.md §"Double-Check Logic Before Compute"` |
| Cross-pillar bridge entries (5-anatomy + 3-level) | `.claude/rules/cross-pillar-bridge-anatomy.md` |
| `a_n^{regulator}` tagging on Seeley-DeWitt citations | `.claude/rules/regulator-pin-discipline.md` |
| Substrate-IS framing in every gate's `substrate_framing` field | `.claude/rules/phononic-framing.md` |

### Investigation-specific

| Concern | Discipline |
|:--------|:-----------|
| `gate_type` set on every gate | One of compute/review/workshop; absent ⇒ compute (a session gate that wandered in). Mixed waves are normal. |
| review/workshop closure | Artifact-existence-with-content (== `wave-classification.md §M1`); NO verdict line; NOT PRU-vulnerable for lacking a numeric threshold. |
| workshop gate = exactly 2 agents | Per `/rclab-workshop` Phase-0 validation. A "workshop" with 1 or 3+ agents is mis-typed → re-type as review. |
| Seed traceability | Every gate item traces to a specific seed finding (gap G-x / contradiction C-x / assumption A-x / refinement R-x / bridge B-x / highest-leverage-next-step). No invented items — the seed is the scope, the way prior-session WP carry-forwards are the scope in session mode. |
| Index registration | `/rclab-plan --investigation` registers `investigation-{n}` in `sessions/investigation/index.md` at plan-freeze (topic + driver/seed + PLANNED status). `/rclab-investigate` housekeeps it on close. Both touch the index; neither invents rows. |
| Verdict track | compute gates pin `verdict_source: computations/investigation-{n}/inv{n}_gate_verdicts.txt`, NEVER a `session-{N}` path. |

A compute gate block missing any required PRDR field, or pinning a non-canonical verdict-file
path, is PRU-vulnerable and will not pass the validator suite. A review/workshop gate is validated
by its `review:`/`workshop:` block + artifact-existence output_artifacts instead.
