## Session Orchestration

A session is partitioned into **waves**; each wave's gates are dispatched to the most-specific research agent. The matured dispatch patterns:

- **Compute waves** (`/rclab-coordinate`) — independent parallel computation; each gate produces a computation script, an `.npz`/`.png` artifact, a working-paper section, and a **dual-SHA verdict line** (content + audit hash) under a pre-registered threshold.
- **Workshops** (`/rclab-workshop`, `/rclab-team`) — 2+ agents with *competing* readings of a specific tension, run in R1-steelman / R2-rebut / R3-converge rounds, producing a structural verdict (not a queued computation).
- **Reviews** (`/rclab-review`) — N independent agents write parallel reports on the same prompt; convergence-despite-divergence is the signal.

Every wave is pre-registered at plan-freeze, audited (PRU cardinality → source reconciliation → substrate-first provenance → PRDR machinery enumeration), executed, then closed by a v3 ladder audit. Session outputs are compressed into dense handouts — decisions, results, equations, constraints — so agents always work from situational awareness, never raw transcripts.

## Replication Guide

To replicate this methodology for a different research program:

1. **Define a central hypothesis** with enough precision to be *closable*.
2. **Identify 6–10 relevant research domains** — curate 10–20 key papers per domain in markdown.
3. **Create domain-specialist agents** pointing at those folders, with mandated rigor and substrate-first framing.
4. **Create a few "Giant" agents** embodying distinct methodological archetypes, plus one "Dreamer" for cross-domain pattern detection.
5. **Pre-register constraint conditions BEFORE computing** — define what would destroy the hypothesis.
6. **Pin the machinery, not just the threshold** (PRU discipline) — unpinned parameters are execution-time freedom.
7. **Run structured waves** (compute / workshop / review) and close every gate with a dual-SHA verdict.
8. **Compress session outputs** into handouts — never let agents work from raw transcripts.
9. **Maintain agent memory** for institutional knowledge; keep project-level facts in registries, not agent memory.
10. **Trust mid-session operator instincts** — two-word redirections consistently outperform hours of agent discussion.
11. **Build a methodology floor early.** The disciplined-dispatch infrastructure (PRU, dual-SHA, layer-functor F) is what lets later sessions trust earlier ones; this project did not have it until ~S78–S81, and the cost of retrofitting was high.

## Epistemological Contribution

The deepest insight of this project is not about physics. It is about what LLMs actually are when used this way.

**Standard framing:** LLMs are "just pattern matching."

**Actual truth:** Mathematics *is* pattern matching. The unreasonable effectiveness of mathematics in physics is precisely the claim that patterns recur across domains.

The training data already contains all of Connes and all of Volovik and all of Baptista and all of random-matrix theory and all of structural acoustics. These sit in separate compartments because no one asks the question that connects them. This system creates contexts where cross-domain connections are *forced* to surface — Tesla sees acoustic impedance in the Lichnerowicz operator because acoustic-physics papers and KK-geometry papers are placed in the same context with the mandate: "What resonates?" If the connections are real, the system finds real physics. If not, the constraint conditions fire.

The constraint conditions keep not firing... but the stabilization mechanisms keep closing (287+ of them). 2–4% is not proof — and it is the project's least-trustworthy number. But it is not nothing: the methodology is sound, the next computation is always defined, the framework has matured a discipline floor that makes its own claims auditable (and has used it to *retract its own over-claims*), and **the mathematics stands on its own regardless of whether the cosmological interpretation survives.**
